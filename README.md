# 赛盟微商城

## 1. 项目目标

赛盟微商城用于搭建一个进口商品共享与分销平台，覆盖以下业务端：

- 小程序端：后续使用微信原生开发，本仓库暂不承载。
- WEB 端：面向终端客户与分销客户的商城站点。
- 分销商管理后台：面向入驻分销商的商品、订单、客户、营销管理。
- 赛盟运营管理后台：面向平台运营方的商品、分销商、会员、资质、风控、营销与经营分析。

核心业务是平台化线上商城，支持分销商入驻、自主分销商品，以及平台统一管理商品、分销商、会员和运营活动。

关键业务规则：

1. 商品上架分两类来源：平台运营直接上架，或分销商上传后经平台审核入公海库。
2. 分销商入驻后，可从公海库挑选商品加入自己的分销库，并生成分销链接。
3. 分销商也可上传自有商品，审核通过后不仅可自销，也可进入公海库供其他分销商选择。
4. 用户注册后先完成实名认证成为客户角色；完成分销商认证后，在保留客户权限的同时新增分销权限。

## 2. 首期建设范围

首期聚焦可上线的交易底座与后台治理能力：

1. 商城基础能力：商品、分类、购物车、下单、支付占位、订单履约、售后。
2. 分销商体系：入驻申请、审核、店铺资料、商品分销、订单查看、客户管理、分销链接生成。
3. 平台运营体系：商品总库、公海库管理、分销商审核、会员管理、订单管理、资质审核、基础数据看板。
4. AI 能力一期：商品卖点生成、营销文案生成、客户跟进话术生成、售后问答知识库占位、商品搭配推荐占位。
5. 风控合规一期：入驻资质上传、审核流、有效期预警。

首期默认业务闭环：

1. 游客注册账号后完成实名认证，成为客户。
2. 客户可直接购买平台商品。
3. 客户申请分销商入驻并通过审核后，账号新增分销角色。
4. 分销商可从公海库选品进入自己的分销库，也可提报自有商品等待审核。
5. 审核通过的分销商自有商品进入公海库，成为平台共享商品池的一部分。

暂不纳入首期开发：

- 小程序前端代码实现。
- 好业财深度集成。
- 进口商实时库存打通。
- 自动拼柜、销量预测驱动物流方案。
- 竞品抓价真实爬虫链路。
- 对账自动生成正式财务闭环。

## 3. 技术方案

### 前端

- React
- TypeScript
- Vite
- shadcn/ui
- Ant Design
- Node.js
- npm workspaces

说明：`shadcn/ui` 负责基础设计系统与页面骨架，`Ant Design` 仅用于后台复杂表格、筛选、日期、树形与批量操作类企业组件。

### 后端

- Java 17
- Maven
- Spring Boot 3
- Spring Security
- MyBatis-Plus
- MySQL 8
- Redis

说明：ORM 明确采用 `MyBatis-Plus` 持续推进；权限体系首期继续基于 `Spring Security + JWT` 深化实现，不切换到 `Sa-Token`。

### 架构原则

- 当前阶段采用“模块化单体 + 清晰领域边界”。
- 单仓多应用：前端多应用工作区 + 后端 Maven 多模块。
- 先统一账号、商品、订单、分销、会员、AI、风控领域模型。
- 后续若业务量增长，可将 AI、搜索、营销、风控拆分为独立服务。

## 4. 推荐参考基座

1. 前端后台 UI 参考：`falcolee/e-commerce-dashboard`
   - React + TypeScript + Vite + Tailwind + shadcn/ui + Ant Design 组合与本项目高度匹配。
2. 后端商城领域参考：`macrozheng/mall`
   - 商品、订单、会员、营销、后台权限等领域拆分成熟，适合作为 Java 商城业务参考。

说明：本项目不会直接照搬原项目代码，而是借鉴其模块拆分、菜单结构与领域设计。

## 6. 当前推进顺序

1. 明确需求边界与角色权限。
2. 搭建 monorepo 骨架。
3. 搭建前端三端路由、布局、设计系统与 API 基础层。
4. 搭建后端多模块、认证鉴权、统一返回、基础领域模型。
5. 落库商品、分销商、会员、订单、资质审核核心链路。
6. 补 AI 能力一期接口，统一调用 Kimi K3，并对接素材生图能力。
