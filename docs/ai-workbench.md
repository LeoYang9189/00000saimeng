# AI 工作台开发约定

## PDF 下载

- 智能选品及商品分析结果右上角提供“下载 PDF”，直接保存文件；选品使用横向 A4，分析报告使用纵向 A4。文件名包含品类/品牌或商品名和本地导出日期。
- 选品包含完整六列表格、估算/待核实提示和知识来源；分析包含四张完整图表、销量及调价明细、模拟分销商数据、竞品评分、详情页初审、运营策略及模拟口径。长内容按行分页，跨页表格重复表头。
- 分析报告未完成时按钮禁用，导出期间显示加载状态并防止重复点击。PDF 在浏览器本地生成，不新增后端接口、不重新调用 Kimi、不上传报告内容。
- `decisionPdf.ts` 动态加载 jsPDF，按页高分辨率绘制中文及重新渲染 ECharts，避免页面滚动、窄屏或折叠状态截断内容。当前 PDF 为图像型页面，文字不可直接选择或搜索；图表使用已生成结果数据，非实时重新分析。
- 验证：独立 Edge 浏览器实际点击两类下载按钮并保存 PDF；检查横向/纵向 A4、中文显示、图表及价格表。压力测试覆盖超长单行跨8页、未完成报告拒绝导出、图表临时节点释放及页面无异常。测试脚本位于 `output/verify-decision-pdf.cjs`，生成的验收文件位于 `output/verify-*.pdf`。

## 界面方向

沿用运营后台的阿里巴巴普惠体、白色内容面和蓝色操作色。基础色：正文 `#162033`、次级文字 `#6b778c`、品牌蓝 `#1f5eff`、分隔线 `#e2e8f0`、页面底色 `#f2f5fa`、内容白 `#ffffff`。

工作区最大宽度 980px，标题 23–30px、正文 14px、辅助文字 12px。技能插画是唯一较强的视觉元素：透明背景、55px（窄屏 46px）、无圆形容器或底座。移除标题装饰线、大面积光晕、复杂技能类型筛选和未接入的工具按钮。

布局：

```text
Shelly 头像  今天，想为生意做点什么？          新建对话
            选品、分析、创作与业务问答，从一个具体任务开始。

  对话记录 / 创作需求与生成结果

  [素材优化] 商品 → 发布渠道 → 视觉风格
  [补充要求输入框]
  [+ 添加技能]                       Ctrl+Enter  [↑]

  透明图标  透明图标  透明图标  透明图标  透明图标  透明图标
  素材优化  商品文案  智能选品  商品分析  客户跟进  业务问答
```

商品来自后台商品库，素材创作一次选择一个已启用且审核通过的商品。渠道固定为小红书图文、朋友圈海报、横版海报、A4 宣传单。视觉风格固定为品牌极简、生活方式、轻奢质感、自然清新、节日礼赠、促销醒目。

## 模型与边界

取消服务商、模型库、网关和 AI 设置页面。文本能力统一经过后端 `KimiClient`，固定模型 `kimi-k3` 和国内 Moonshot API。密钥读取后端配置 `MOONSHOT_API_KEY`，不进入前端或数据库配置页面。

官方接入依据：https://platform.kimi.com/docs/guide/kimi-k3-quickstart

K3 文档提供文本输出和视觉理解接口；本项目使用它生成宣发文案和图片创作指令。图片生成通过独立 Lovart 适配器调用，不假设不存在的生图 API。

缺少密钥时只整理创作需求与固定提示词，明确返回等待开通状态，不伪造 AI 文案、图片或完成状态。A4 使用 2480 × 3508 像素的目标尺寸，后续图片适配器仍需处理印刷导出要求。

旧 AI 配置数据表保留历史数据，不再参与运行时路由或密钥读取。

## 接口与后续接入

- `GET /api/admin/ai/workbench`：固定模型、可用状态、渠道和风格枚举。
- `POST /api/admin/ai/workbench/materials`：只接收商品 ID、渠道、风格和补充要求，商品事实在后端读取，返回创作需求、文案和图片状态。
- `POST /api/admin/ai/workbench/chat`：普通对话与其他文字技能统一调用 Kimi K3。
- 接口复用运营后台权限，普通用户和分销商不能调用这些运营接口。

Kimi 密钥由启动后端的进程环境变量 `MOONSHOT_API_KEY` 注入。当前没有自动读取 `.env` 的逻辑。提供密钥后需要重启后端；无需更改前端或进入系统设置。密钥不应写入源码、前端环境变量或文档。

后端从 `server/saimeng-admin` 启动，保留已有本地数据库：

```powershell
java.exe -Dfile.encoding=UTF-8 -jar target/saimeng-admin-0.1.0-SNAPSHOT.jar --spring.profiles.active=local --spring.sql.init.mode=never --server.address=127.0.0.1
```

图片能力入口为 `MaterialImageGenerator`，运行时使用 `LovartMaterialImageGenerator`。它按照本机 `lovart-media` 技能的 OpenAPI 协议签名调用，读取 `LOVART_ACCESS_KEY`、`LOVART_SECRET_KEY` 和 `LOVART_PROJECT_ID`。支持商品库中的公网 HTTPS 参考图；本地 `/home/` 图片需配置 `AI_REFERENCE_ROOT` 为商城 public 目录，服务端校验实际路径、图片扩展名和 15MB 限制后上传至 Lovart。缺少参考图会返回补图状态，不虚构商品包装。生图失败时保留成功生成的文案。

参考素材仅取所选商品的 `mainImage`，不追加 `galleryImages` 或回退至 `thumbnailImage`。选择商品和结果卡片均预览同一主图；缺少主图时在调用模型前提示补图。本地主图上传后，将返回的公网 URL 同时写入 Lovart 提示词和唯一 `attachments` 附件，明确保持该商品包装和标签，不使用历史项目素材。商品主图本身与名称不符时仍需在商品中心修正，不能强制让模型虚构正确包装。

## 对话流

运营前端使用 Ant Design X `Bubble`、`Sender` 和 `XMarkdown`。提交后创作表单和快捷技能收起，点击“继续对话”“编辑这条需求”或“调整需求”才再次展开。

- `POST /api/admin/ai/workbench/chat/stream`：Kimi 原生 SSE 增量回答，只转发 `delta.content`，不展示推理字段。
- `POST /api/admin/ai/workbench/materials/stream`：`stage` → `prompt_delta` → `material`（文案已生成）→ `stage`（等待图片）→ `material`（最终状态）→ `done`。
- 错误使用 `error` 事件，客户端保留已生成文本、文案及原始需求；没有收到 `done` 的断流不会标记成功。
- Lovart 最长轮询十分钟。费用确认不会自动批准；中止、未返回图片、部分失败和超时分别提示。超时后可凭任务编号在 Lovart 项目中检查，不应立即重复提交。
- “停止等待”关闭浏览器连接，不等同于取消已提交的 Lovart 远程任务。

本地密钥可写入 Git 忽略的 `server/saimeng-admin/application-local.yml`，以 `--spring.profiles.active=local` 启动加载。环境变量仍然可用；不要将实际密钥写入文档或前端。

本机 `AI_REFERENCE_ROOT` 为 `../../apps/web-store/public`（后端从 `server/saimeng-admin` 启动）。运营 Vite 将 `/home` 代理到商城 5173，保证商品预览可用。正式部署时需使用统一媒体域名或配置对应静态资源服务。本项目仍为本地预览鉴权，不能直接公开部署携带真实 AI 密钥的后端。

本次实现范围是运营后台工作台；分销商原有工作台的其他业务工作流仍待后续开发。

## 图标资产

六个技能图标使用内置 `image_gen` 分别生成，文件位于 `apps/operation-admin/public/ai-skills/`，包含真实 alpha 通道。提示词保存在 [ai-icon-prompts.json](./ai-icon-prompts.json)。图标不包裹背景容器。
