# AI 工作台开发约定

## 界面方向

沿用运营后台的阿里巴巴普惠体、白色内容面和蓝色操作色。基础色：正文 `#162033`、次级文字 `#6b778c`、品牌蓝 `#1f5eff`、分隔线 `#e2e8f0`、页面底色 `#f2f5fa`、内容白 `#ffffff`。

工作区最大宽度 980px，标题 23–30px、正文 14px、辅助文字 12px。技能插画是唯一较强的视觉元素：透明背景、55px（窄屏 46px）、无圆形容器或底座。移除标题装饰线、大面积光晕、复杂技能类型筛选和未接入的工具按钮。

布局：

```text
Shelly 头像  今天，想为生意做点什么？          新建对话
            选一件商品，把灵感变成下一份推广内容。

  对话记录 / 创作需求与生成结果

  [素材优化] 商品 → 发布渠道 → 视觉风格
  [补充要求输入框]
  [+ 添加技能]                       Ctrl+Enter  [↑]

  透明图标  透明图标  透明图标  透明图标  透明图标  透明图标
  素材优化  商品文案  智能选品  商品分析  客户跟进  业务问答
```

商品来自后台商品库，素材创作一次选择一个已启用且审核通过的商品。渠道固定为小红书图文、朋友圈海报、横版海报、A4 宣传单。视觉风格固定为品牌极简、生活方式、轻奢质感、自然清新、节日礼赠、促销醒目。

## 模型与边界

取消服务商、模型库、网关和 AI 设置页面。文本能力统一经过后端 `KimiClient`，固定模型 `kimi-k3` 和国内 Moonshot API。密钥只读取后端环境变量 `MOONSHOT_API_KEY`，不进入前端或数据库配置页面。

官方接入依据：https://platform.kimi.com/docs/guide/kimi-k3-quickstart

K3 文档提供文本输出和视觉理解接口；本项目使用它生成宣发文案和图片创作指令。图片生成通过独立适配器预留，待提供 Lovart Skill 后实现，不假设不存在的生图 API。

缺少密钥时只整理创作需求与固定提示词，明确返回等待开通状态，不伪造 AI 文案、图片或完成状态。A4 使用 2480 × 3508 像素的目标尺寸，后续图片适配器仍需处理印刷导出要求。

旧 AI 配置数据表保留历史数据，不再参与运行时路由或密钥读取。

## 接口与后续接入

- `GET /api/admin/ai/workbench`：固定模型、可用状态、渠道和风格枚举。
- `POST /api/admin/ai/workbench/materials`：只接收商品 ID、渠道、风格和补充要求，商品事实在后端读取，返回创作需求、文案和图片状态。
- `POST /api/admin/ai/workbench/chat`：普通对话与其他文字技能统一调用 Kimi K3。
- 接口复用运营后台权限，普通用户和分销商不能调用这些运营接口。

Kimi 密钥由启动后端的进程环境变量 `MOONSHOT_API_KEY` 注入。当前没有自动读取 `.env` 的逻辑。提供密钥后需要重启后端；无需更改前端或进入系统设置。密钥不应写入源码、前端环境变量或文档。

后端从 `server/saimeng-admin` 启动，保留已有本地数据库：

```powershell
java.exe -Dfile.encoding=UTF-8 -jar target/saimeng-admin-0.1.0-SNAPSHOT.jar --spring.sql.init.mode=never --server.address=127.0.0.1
```

图片能力入口为 `MaterialImageGenerator`。当前 `PendingMaterialImageGenerator` 返回等待接入状态；接入 Lovart 时实现此接口并替换当前组件。输入已包含商品参考图、目标尺寸和完整创作指令。生图失败时保留成功生成的文案。K3 的真实联网生成与 Lovart 生成需在拿到密钥和 Skill 后验证。

本次实现范围是运营后台工作台；分销商原有工作台的其他业务工作流仍待后续开发。

## 图标资产

六个技能图标使用内置 `image_gen` 分别生成，文件位于 `apps/operation-admin/public/ai-skills/`，包含真实 alpha 通道。提示词保存在 [ai-icon-prompts.json](./ai-icon-prompts.json)。图标不包裹背景容器。

## 本次验证

- `mvn.cmd package`：通过，10 项 AI 服务与 HTTP 客户端测试全部通过；测试使用本地模拟响应，没有使用真实 Kimi 密钥。
- 运营端、分销商端生产构建通过；新增工作台代码 lint 无错误或警告，项目其他页面原有警告未修改。
- 本地接口验证：4 个渠道、6 种风格、无密钥状态、无效渠道/风格/商品校验、未登录与分销商访问限制。
- 浏览器验证：商品搜索及空状态、依次选择、切换渠道/风格、提交需求、恢复并调整需求、复制反馈、快捷发送及保留失败输入。

目前服务继续运行在 5173（客户端）、5174（运营后台）、5175（分销商后台）和 8080（后端），进程与日志位置记录在 `logs/dev-frontends.json`、`logs/dev-backend.json`。
