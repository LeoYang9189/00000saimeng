# 赛盟微商城系统架构设计

## 1. 架构结论

首期采用：

- 前端：Monorepo 多应用架构
- 后端：Spring Boot 模块化单体
- 数据库：MySQL
- 缓存：Redis
- 鉴权：JWT + Spring Security
- ORM：MyBatis-Plus
- AI：独立领域模块，通过统一 AI 服务接口接入模型能力

原因：

1. 业务复杂，但首期团队需要快速落地。
2. 微服务会放大部署、链路、测试和联调成本。
3. 当前需求核心是先把商城交易、分销入驻、运营治理和 AI 辅助做通。
4. 模块化单体更适合前期快速迭代，后续可平滑拆分。

## 2. 总体结构

```text
前端层
├── web-store            商城 WEB 端

├── saimeng-marketing    营销中心
├── saimeng-ai           AI 能力中心
└── saimeng-common       通用基础模块
```

## 3.2 组件策略

- `shadcn/ui`：导航、弹层、基础表单、布局骨架。
- `Ant Design`：后台表格、日期、树、复杂筛选、批量操作。
- 统一 Token：颜色、间距、圆角、字体在共享层维护。

## 3.3 路由策略

- 各应用使用独立路由。
- 管理后台采用布局路由 + 权限路由元数据。
- 商城 WEB 端采用公共页面路由 + 用户中心路由。

## 5. 权限模型

采用 RBAC：

- 平台运营用户
- 分销商管理员
- 分销商员工
- 普通会员

账号与角色关系：

1. 一个账号可同时绑定多个角色。
2. 注册账号默认无交易权限，完成实名认证后获得客户权限。
3. 客户发起分销商入驻并审核通过后，新增分销商角色。
4. 分销角色是增量授权，不覆盖客户角色。

数据隔离规则：

1. 平台运营可见全量数据。
2. 分销商只能访问自身店铺与订单数据。
3. 会员只能访问自己的订单、地址和个人资料。
4. 分销商从公海库选中的商品，仅生成分销关系数据，不复制商品主档。

## 5.1 商品流转模型

商品分为两种来源：

1. 平台运营上传商品：审核后直接进入公海库，可供分销商选品。
2. 分销商上传商品：提交后进入待审，审核通过后进入公海库，同时保留商品来源分销商标记。

商品与分销关系分离：

1. `product_spu` / `product_sku` 保存商品主数据。
2. 分销商选品后，通过关系表记录“哪个分销商分销哪个商品”。
3. 分销链接挂在分销关系上，而不是挂在商品主档上。

## 6. AI 模块落地方案

首期不把 AI 写死到业务流程里，而是通过统一服务接口解耦。

### 首期接口

- `generateProductSellingPoints`
- `generateMarketingCopy`
- `generatePrivateChatScript`
- `calculateOrderProfit`
- `answerAfterSalesQuestion`

### 输入来源

- 商品基础信息
- 商品资质信息
- 分销商客户信息
- 订单数据
- 平台预设提示词模板

### 输出去向

- 分销商后台 AI 助手
- 运营后台 AI 配置与审核页面

## 7. 数据库原则

- 所有主表包含：`id`、`created_at`、`updated_at`、`deleted`
- 禁止 `select *`
- 所有分页接口设置上限
- 所有写操作保留操作人字段
- 数据访问层统一采用 `MyBatis-Plus`，复杂查询再补充自定义 Mapper SQL
